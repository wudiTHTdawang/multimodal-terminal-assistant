# 模型与端侧部署说明

## 运行边界

比赛版本运行于普通 Windows 笔记本：Python 本地服务仅监听 `127.0.0.1`，浏览器通过本机摄像头完成视线、头部和手势推理。冲突解释和个性化语言组织使用本机 Ollama 中的 `qwen2.5:3b-instruct`（约 3.09B 参数，低于赛题 14B 上限）；不调用云端推理服务。

## 本地大模型的职责与安全边界

`llm_reasoner.py` 只向 `http://127.0.0.1:11434` 发送脱敏后的结构化结果：页面名称、已识别意图、视线目标 ID、确认/取消动作、用户画像中的应答风格，以及日程的聚合数量统计。它不接收原始摄像头画面、音频、完整备忘录或第三方应用数据。

- **规则模块负责**：时间对齐、联系人/日程对象有效性校验、显式取消优先、必须确认的安全门，以及本地状态写入；
- **大模型负责**：解释语音与视觉冲突、将规则结论组织成更自然且符合画像风格的中文应答；
- **不可越权**：大模型输出不能改变意图、对象、消息内容、是否执行或完成状态；
- **延迟兜底**：模型只生成紧凑 JSON（单字段最多 20 字，最多 32 token），单轮推理时间预算 2.8 秒。模型未启动、冷启动、输出不合规或超时均立即回退到规则模板，保证交互可继续进行。

首次请在 PowerShell 运行 `ollama pull qwen2.5:3b-instruct`，随后运行 `ollama serve`（若 Ollama 已作为后台服务启动，则无需重复启动）。项目启动后会按需加载模型；演示前可先发起一次无关紧要的查询完成预热。

## 本地视觉组件

| 组件 | 本地文件 | 作用 | 推理位置 |
| --- | --- | --- | --- |
| MediaPipe Face Landmarker | `web/models/face_landmarker.task` | 人脸关键点、视线特征、点头/摇头特征 | 浏览器 |
| MediaPipe Gesture Recognizer | `web/models/gesture_recognizer.task` | 点赞、踩、手掌开合、挥手等手势特征 | 浏览器 |
| MediaPipe Tasks Vision 1.0.1 | `web/vendor/mediapipe/` | 浏览器端视觉运行时和 WASM 执行环境 | 浏览器 |

模型、运行时与 WASM 均随代码包发布，不从 CDN 下载。原始摄像头帧只在浏览器内存中处理；后端仅接收“注视到哪个本地页面对象、置信度、停留时间、确认动作”等结构化结果。

## 启动与验收

1. 在项目根目录运行 `python app.py`。
2. 浏览器访问 `http://127.0.0.1:8000`。
3. 开启摄像头，完成九点视线校准。
4. 断开网络后刷新页面，再次开启摄像头；模型加载成功即证明视觉运行时不依赖外网。
5. 在“查看本轮本地多模态处理记录”中查看事件和 P50/P95 本地接口延迟。
